\begin{abstract}
Large integer multiplication is critical in cryptographic applications such as Fully Homomorphic Encryption (FHE) and RSA where it represents the main step in computing the modular multiplication used to generate keys.
Most previous work building such multipliers on FPGAs has overlooked the importance of considering the underlying architecture of the Digital Signal Processing (DSP) Blocks present in modern FPGAs. 
These DSP blocks have an irregular input size that must be tiled carefully to create larger multipliers, and have complex pipelining configurations, which must be respected to achieve high frequency.
We show how to build efficient base multipliers that can then be tiled to large sizes efficiently through automated architecture-aware tiling and fast pipelined datapath generation, while maintaining resource efficiency and high throughput.
We demonstrate full automation of large multiplier generation, achieving 56\% higher frequency while using about 17\% fewer DSP blocks compared to prior approaches.
\end{abstract}

\section{Introduction}
While multiplication is conceptually simple, implementing it efficiently becomes difficult at large sizes.
Large integer multiplication is especially important in cryptography, where common sizes include 160--512 bits for Elliptic Curve Cryptography (ECC) and 1024--4096 bits for RSA~\cite{patelComparisonKeySize2023}.
These large sizes must be built from the smaller primitives available on a target architecture.

Field-Programmable Gate Arrays (FPGAs) offer a flexible architecture that can be used to implement a variety of applications in domains such as image processing,  digital signal processing~\cite{sarrafzadehImageRestorationFPGA2003}, and cryptography~\cite{prasannaFHEPerformanceModelingFPGA2021}.
Because multiplication is a common operation and expensive to implement in LUTs, FPGAs have provided dedicated DSP blocks that deliver higher throughput and better area/energy efficiency than LUT implementations.
DSP blocks also support common arithmetic patterns (e.g. multiply-accumulate). However, achieving an optimal balance of DSPs and LUTs for large, structured arithmetic remains challenging.

Large multipliers are typically constructed by decomposing operands into smaller tiles that match the underlying DSP wordlengths.
Schoolbook decomposition computes multiple partial products and combines them with shifts and additions, while Karatsuba decomposition~\cite{karatsubaOriginalPaper} reduces the number of multiplication operations in exchange for additions/subtractions (Section~\ref{sec_background}).
For extremely large sizes, FFT~\cite{yapFFTquickmul2000} and NTT~\cite{weemsNTTHighPrecisionInteger2011} based methods are also possible.

Effective large multiplication decomposition on FPGAs must consider the underlying architecture to achieve high performance and resource efficiency: DSP primitives are asymmetric with non-power-of-2 wordlengths, signed/unsigned handling affects tiling, and achieving high frequency requires respecting DSP pipeline constraints.
FPGAs also expose additional structures such as cascade paths that can improve both performance and resource usage when exploited.
This paper addresses large integer multiplication in an architecture-aware manner, enabling both efficient base multipliers and scalable large multipliers on FPGAs.

The main contributions of this paper are: 
\begin{enumerate}
    \item A method for building architecture-aware base multipliers that map efficiently to FPGA DSP blocks while achieving high frequency and low resource usage, shown to outperform vendor 64-bit IP multiplier.
    \item Automated construction of large multipliers from the proposed base designs using Schoolbook and Karatsuba decompositions, with FPGA-aware pipelining and mapping.
    \item Evaluation across operand sizes and base sizes, including a 1024-bit-bit design compared against an optimized HLS implementation and the state-of-the-art approaches in~\cite{zhangIMpressLargeInteger2022} and ~\cite{kummTilingHeuristics2020}.
    \item An open-source tool for generating large multipliers on AMD FPGAs, which will be released with the paper for the wider community.

\end{enumerate}

\section{Background} \label{sec_background}
\subsection{Decomposition Schemes}
Large multipliers are typically built by decomposing the computation across smaller multipliers with shift-and-add operations combining these to form the final result.

\noindent\textbf{Schoolbook Decomposition} forms a $2n\times 2n$ product using four $n\times n$ partial products (Equation~\ref{schoolbook_eq}). Let $A=(A_1\ll n)+A_0$ and $B=(B_1\ll n)+B_0$; with reference to Fig.~\ref{fig:schoolbook_decomp}:
\begin{equation} \label{schoolbook_eq}
\begin{split}
    \mathit{Schoolbook}(A \times B) = & P1 + (P2 \ll 2n) \\
                &+ ((P3+ P4) \ll n) \\
\end{split}
\end{equation}
This approach scales to more splits (e.g., nine multipliers for a $3\times 3$ split) and relies on more shift-and-add logic to combine partial products.
Equation~\ref{schoolbook_eq} can be rearranged to trade an addition for zero cost concatenation~\cite{zhangIMpressLargeInteger2022}:


\begin{equation} \label{trick_schoolbook_eq}
    (P1 +(P2 \ll 2n)) = \{P2, P1\}
\end{equation}

\noindent\textbf{Karatsuba Decomposition}~\cite{karatsubaOriginalPaper} reduces the number of multiplications needed in the $2\times2$ case from four to three by replacing one multiplication with additions/subtractions.
One product is typically $(n{+}1)$ bits wide.
Fig.~\ref{fig:karatsuba_vs_schoolbook} compares Schoolbook and Karatsuba for a $2n \times 2n$ multiplier. 
Karatsuba can be extended to larger grids (e.g., $3\times3$), saving three multipliers relative to Schoolbook (which uses $9$ multipliers).
\begin{equation} \label{karatsuba_eq}
\begin{split}
    \mathit{Karatsuba}(A_0  B_1 + A_1  B_0) = P3-P1-P2
\end{split}
\end{equation}

\subsection{DSP Block Consideration}
\noindent\textbf{Overview and Applications.}
A DSP block is a hard FPGA primitive optimized for high-frequency multiply-add/accumulate operations. Modern architectures have increased multiplier widths (e.g., $25\times18$ in Virtex-5/6/7, $27\times18$ in UltraScale(+), and $27\times24$ in Versal).
They are widely used in FIR filters, ML inference, and scientific signal processing~\cite{xilinxVirtex-4DSPExplainedFPGA,ghiasiDSPEfficientCNNFPGA2020}; some generations also support floating-point modes~\cite{pascaFloatingPointDSPBlock2015}.


\noindent\textbf{AMD DSP Block Architecture.}
An AMD DSP48E2 block integrates a pre-adder (not shown nor used in this work), multiplier, multiplexers, and an ALU (Fig.~\ref{fig:cascade_comparison}).
Control signals (e.g., OPMODE/ALUMODE) select the datapath/ALU expression~\cite{UltraScaleArchitectureDSP2021}, and optional pipeline registers trade latency for throughput (enabling all four registers yields maximum throughput).
Cascaded ports (e.g., PCIN/PCOUT) support efficient column-wise chaining.
Correct multiplier and cascade behavior requires routing the multiplier partial products to the $X$ and $Y$ multiplexers while selecting the appropriate $Z$ source (e.g., PCIN) via OPMODE.

\noindent\textbf{Chaining DSP Blocks.} \label{sec_dsp_cascade}
More than one DSP block can be chained to create wider multipliers.
For instance, two DSP blocks can be chained to perform a $44\times18$ multiplication.
Assuming two inputs $K$ of size $44$ bits and $M$ of size $18$ bits,
$K$ is split into two parts: the lower $17$ bits ($K_L$) and the upper $27$ bits ($K_H$).
To fit within the 48-bit datapath and leverage the built-in 17-bit right shift, the accumulation is rewritten as follows:

\begin{equation} \label{dsp_cascade_shift_eq}
\begin{split}
    P1 &= (K_L\times M), \quad P2 = (K_H \times M)\\
    K\times M &=  \{(P2 + (P1 \gg 17)),
            \ P1[16:0]\}
\end{split}
\end{equation}

Fig.~\ref{fig:cascade_comparison} contrasts two chaining options: the PCOUT-to-PCIN cascade path versus routing P-to-C.
With PCOUT-to-PCIN, S1 cascades PCOUT to S2 PCIN and uses the built-in 17-bit right shift in S2.
Signal synchronization requires delaying $K_H$, $M$, and the extracted LSBs from P1, resulting in a 5-cycle latency, but no additional hardware usage.
Because the cascade path supports only 0 or 17-bit shifts, other shift amounts must use the P-to-C path which requires shift/sign-extension (ExSRn) and routing S1's P to S2's C, typically adding an extra pipeline stage for signal synchronization.

\subsection{Signed vs Unsigned Multiplication} \label{sec_sign_unsigned_mult}
When constructing large multipliers from smaller ones, signedness must be handled carefully.
In decomposition, only the multipliers dealing with MSBs should be signed (for a signed multiplication); all other partial products must be computed unsigned even if the overall multiplication is signed.
A signed $n$-bit multiplier can be used as an unsigned $(n{-}1)$-bit multiplier by zero-padding the MSB.
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%


\subsection{IP Multipliers} \label{sec_ip_background}
AMD provides an IP multiplier in Vivado~\cite{xilinxincIPMultiplier2015} that generates parameterized signed/unsigned multipliers up to $64\times64$ bits, with options to optimize for frequency or resource utilization and a recommended pipeline depth.
For sizes larger than $47\times47$ bits, only the performance-optimal design is offered; it achieves maximum DSP frequency but consumes more DSP blocks than necessary.

\section{Large Multiplier Design} \label{sec_large_mult_design}
Our approach focuses on building efficient base multipliers using DSP blocks, then hierarchically tiling them up to large sizes while considering the FPGA architecture and DSP block features and using fast pipelined combinational logic.

\subsection{Building Base Multipliers} \label{sec_build_base_mult}

%% here explain the algorithm and its caveats and why it is not always a square area. 

% Explain the tiling algorithm and how it works (cite Roy et al.~\cite{royTileMultiplicationEfficient2014})
To construct large multipliers efficiently on FPGAs, we build base multipliers and tile them to larger sizes.
Karatsuba decomposition can only combine partial products that are aligned to the same shift amount.
For a $W_1\times W_2$ base, shifts take the form $W_1 n + W_2 m$ and Karatsuba-friendly shift amounts take the form $k\cdot\frac{W_1 W_2}{\gcd(W_1, W_2)}$, where $k$ is an integer.
Thus, rectangular bases only yield sparse Karatsuba-friendly alignments (e.g., $26\times17\Rightarrow 442k$).
Square bases yield more Karatsuba-eligible partial products (e.g., $44\times44\Rightarrow 44k$), allowing more opportunities for reducing the number of multipliers used.

A square base multiplier can be obtained using a tiling algorithm inspired by Roy et al.~\cite{royTileMultiplicationEfficient2014}.
Given DSP primitive unsigned dimensions $W_1\times W_2$ (e.g., $26\times17$ for the DSP48E2), and a target size $M$,  the algorithm chooses integers $n,m$ so that the covered width
\[
\bar{M} = n \cdot  W_1  + m \cdot W_2 .
\]
where $\bar{M} \geq M$.
Tiles of size $W_1\times W_2$ and $W_2\times W_1$ are placed along the boundary of the $\bar{M}\times\bar{M}$ square, leaving a smaller square region in the middle that is recursively tiled in the same way.
However, the original algorithm has practical limitations that our work addresses:
\begin{itemize}
    \item The remaining middle region is not guaranteed to be a square for arbitrary $n,m$.
    \item Hardware mapping is not architecture-aware (e.g., cascade/shift constraints), and does not explicitly provide variants that trade off LUT usage and latency.
\end{itemize}

To guarantee a square middle region, we constrain one tiling coefficient to 1 (either $n=1$ or $m=1$).
% DSP blocks covering MSB regions can use the full signed range ($27\times18$), while LSB-only regions must use the unsigned range ($26\times17$). 
% Therefore, a tiling yields either an $(n\cdot26+m\cdot17)$-bit unsigned multiplier or an $(n\cdot26+m\cdot17+1)$-bit signed multiplier.
Fig.~\ref{fig_tiling_examples} shows the tiling scheme for 44- and 78-bit signed base multipliers.
To address the remaining issues, we separate generating multiplication terms (tiles) from mapping them to DSP blocks.
This enables architecture-aware mapping (cascade/shift constraints) and optimization for either LUT minimization or latency.
Additionally, small multipliers are automatically mapped to LUTs to save DSP resources for larger widths, and all signals are automatically synchronized.
Fig.~\ref{fig_grouping_strategies} compares two mapping strategies for the 78-bit multiplier.
First, the one-group strategy (Fig.~\ref{fig_one_group}) chains as many terms as possible (sorted in ascending order based on their shift amount) to minimize LUT usage. 
This ordering allows for non-overlapping bit extraction and keeps additions within the DSP48E2 48-bit datapath.
The multi-group strategy (Fig.~\ref{fig_three_groups}) forms independent chains whose terms are shifted apart by 17 bits, maximizing usage of cascade connections and enabling parallel evaluation to reduce latency.

\subsection{Tiler} \label{sec_tiler}
Finding the optimal placement of small rectangles to tile a large rectangle is NP-complete~\cite{BeumontTilingNPComplete2002}.
General tiling schemes suffer from two main limitations when applied to large multipliers on FPGAs:
\begin{itemize}
    \item They do not prioritize hierarchical regions that enable Karatsuba-style factoring.
    \item They ignore architecture-specific features such as DSP cascade capabilities and efficient base sizes.
\end{itemize}

We address these limitations by hierarchically replicating an efficient square base multiplier of size $B\times B$ (Section~\ref{sec_build_base_mult}) using $2\times2$ or $3\times3$ grids that preserve shift alignment for systematic Karatsuba decomposition.
Accordingly, the possible scaled up side lengths are
\[
H = 2^x \times 3^y \times B,
\]
where each factor of $2$ or $3$ corresponds to one hierarchy level.

% The DSP cost of $H$ is determined once the base and the decomposition schedule are chosen.
% Let $D_{base}$ be the DSP count of the base multiplier and $D_{total}$ be the total DSP count of the hierarchical region.
% For a hierarchical side length $H=2^x\times 3^y\times B$, the total DSP count is:

% \begin{equation*}
% D_{total} = D_{base} \times \prod_{i=1}^{L} n_i(n_i - k_i)
% \end{equation*}
% where $L=x+y$ is the total number of hierarchy levels. At each level $i$, $n_i = s_i + 2$ with $s_i\in\{0,1\}$ for 2-way or 3-way split, and $k_i\in\{0,1\}$ for Schoolbook or Karatsuba.


The total DSP usage can be determined once the base and decomposition schedule are chosen.
Let $D_{\mathit{base}}$ be the DSP usage of the base multiplier, then
for a hierarchical side length $H=2^x\times 3^y\times B$, the total DSP utilization is:

\begin{equation*}
D_{\mathit{total}} = D_{\mathit{base}} \times \prod_{i=1}^{L} (\frac{s_i \times (s_i + k_i)}{2^{k_i}})
% D_{total} = D_{base} \times \prod_{i=1}^{L} s_i(s_i - k_i)
\end{equation*}
where $L=x+y$ is the total number of hierarchy levels. At each level $i$, $s_i\in\{2,3\}$ for 2-way or 3-way split, and $k_i\in\{0,1\}$ for Schoolbook or Karatsuba decomposition.

We evaluate two tiling methodologies, compared in Fig.~\ref{fig_overshoot_target_constrained_comparison} for a 1024-bit target multiplier:

\noindent\textbf{Overshoot tiling.}
Instead of forcing an exact target size match, we choose an achieved size $\bar{T}\ge T$ that increases the hierarchical portion (e.g., by selecting a larger $H$ or using a base $B$ with better $2^x\times3^y$ coverage).
This can provide more opportunities for Karatsuba decomposition and thus reduce DSP usage, at the cost of extra LUT-based shift-and-add logic to handle the excess bits.

\noindent\textbf{Target-constrained tiling.}
Alternatively, given a target side length $T$, we first select the largest hierarchical side length $H \le T$ of the form $H=2^x\times3^y\times B$.
This produces a hierarchical $H\times H$ region that can be decomposed cleanly across hierarchy levels; the remaining non-hierarchical rectangular regions are then filled using additional placements.

\noindent\textbf{Tiling the remaining area.}
We explore three variants for this:
(1) greedily placing the same base until it no longer fits, then placing DSP-sized multiplications;
(2) recursively tiling the remainder using other efficient bases (e.g., $44\times44$ and $94\times94$) and small DSP-sized tiles; and
(3) a cascade-compatible variant that prefers placements enabling DSP cascade connections.
In all variants, each candidate placement is scored by DSP count and by estimated LUT/FF overhead for accumulation.
The cascade-compatible variant is preferred in Fig.~\ref{fig_target_constrained_tiling} because it reduces LUT-based shifting and addition while also lowering DSP utilization (464 DSP48E2 blocks versus 507 for the greedy approach and 516 for the non-cascade-compatible variant for the 1024-bit multiplier in Fig.~\ref{fig_overshoot_target_constrained_comparison}).

\subsection{Optimal Base Size Choice}
Base multiplier size strongly affects DSP usage, hierarchy depth, and the amount of irregular remainder tiling (Section~\ref{sec_tiler}).
We evaluate the candidate bases produced in Section~\ref{sec_build_base_mult}.
Bases derived by fixing the larger DSP dimension ($26$ for DSP48E2 $26\times17$) consistently reduce DSP waste (e.g., $43, 60, 77, 94, 111, 128, \dots, 264$).
Within this family, the 77-bit base exhibits the lowest waste when considered in isolation.
However, low DSP waste alone does not guarantee an efficient hierarchy for Karatsuba or Schoolbook decomposition.
We therefore also consider nearby sizes that improve hierarchical coverage, even if they yield a slightly larger achieved size.
For example, tiling the 77-bit base towards a 1024-bit target yields a largest hierarchical block of 924-bits and leaves two non-hierarchical rectangular regions.
In contrast, a 43-bit base can reach 1032-bits and thus increase the hierarchical nature for Karatsuba (Fig.~\ref{fig_overshoot_target_constrained_comparison}).

Since DSP usage and latency are known at design time, we perform a Pareto analysis across targets from 160 to 1024 bits with different bases and decomposition schemes.
Fig.~\ref{fig_pareto_frontier_all_configs} shows that the 43-bit base with Karatsuba decomposition at all levels minimizes DSP usage at the cost of higher latency, while 77- and 128-bit bases with Schoolbook decomposition reduce latency but increase DSP consumption.

\subsection{Fast Pipelined Combinational Logic} \label{sec_fast_pipelined_comb_logic}
The wide combinational paths implementing logic like shift/add/subtract can dominate the critical path in large multipliers.
Therefore, we split the logic into smaller pipelined segments to achieve high throughput.
Empirically, we observe a frequency drop when the segment width exceeds 64 bits.
Our flow makes segment size configurable to trade off depth, latency, and timing.
These intermediate logic segments are pipelined to achieve high throughput; this is done not only at the module level, but also with awareness of the pipeline schedule of individual signals, interleaving pipelining where necessary to reduce overall latency.

\subsection{Automating the Flow}
To enable rapid design-space exploration, we built an automated flow that integrates the components described in the previous sections.
A specification is provided with the target multiplication size, base multiplier dimensions, option desired decomposition strategies (Schoolbook, Karatsuba, or mixed), and the base combinational logic width.
The \textbf{Tiler} first instantiates a grid covering the total size using the base size, with no hierarchy. 
When the target size is not an exact multiple of the base, the remaining regions are filled using DSP block multipliers (Section~\ref{sec_tiler}).
A single hierarchy level exposes limited structure for Karatsuba-style factoring. Hence, the \textbf{Hierarchy Generator} takes this initial flat grid and generates alternative hierarchical combinations of $2\times 2$ and $3\times 3$ grids at different levels.
For example, a flat $12\times 12$ grid can be decomposed into a grid of four $6\times 6$ blocks,  each of which can be a grid of four $3\times 3$ bases, creating three levels of hierarchy (see Fig.~\ref{fig_target_constrained_tiling}).

Each variant is processed by the \textbf{Exporter}, and the \textbf{Visualizer} in parallel.  
The \textbf{Exporter} outputs an intermediate representation of the decomposition scheme that indicates the mathematical operations without timing consideration.
The \textbf{Visualizer} renders the decomposition graphically and checks for correct tiling (100\% coverage with no overlaps).
The \textbf{Software Tester} then validates the untimed intermediate representation via software simulation before hardware generation.
After validation, the \textbf{RTL Generator} takes the intermediate representation and produces timed, optimized, synthesizable Verilog for each module and submodule based on Section~\ref{sec_build_base_mult} and Section~\ref{sec_fast_pipelined_comb_logic}, along with testbenches for functional verification.
The flow also generates Tcl scripts to run FPGA implementation and report area/timing, and generates dataflow diagrams with annotated operations and pipeline synchronization points.

\subsection{Latency Mitigation}
As shown, our primitive-based large multipliers achieve significantly higher frequencies than prior work, but they do suffer from higher latency in cycles.
This can be mitigated by divide the combinational logic into larger segment sizes (e.g., 128 bits instead of 64 bits).
Table~\ref{table_combiner_size} shows the impact of varying the combinational logic segment size on the latency and performance of a 1032-bit multiplier with a 43-bit base multiplier.
Increasing the segment size reduces the latency significantly, trading off slightly increased LUT usage and reduced maximum frequency.
Using a 256-bit segment size reduces the latency from 100 to 58 cycles while still achieving higher frequency than other implementations.
With the significant frequency improvement against previous work, this latency cost can be tolerable for the high throughput improvement.

\section{Related Work}
Authors in~\cite{fahmyMapDSPMaxPerformance2016} developed an automated tool for mapping arithmetic expressions to DSP blocks through DSP-aware pipelining.
% and their extension of multi-pumping for resource sharing while preserving high operating frequency~\cite{fahmyMultipumpingDSP2017}.
However, they relied on fixed template databases that constrain their generalizability and are not suitable for large integer multiplication. 
Authors in~\cite{zhangIMpressLargeInteger2022} presented IMpress, an E-graph framework for large integer multiplication using HLS.
However, it suffers from low frequency.
Extending general decomposition schemes to be architecture-aware has been explored in previous work. 
In~\cite{royTileMultiplicationEfficient2014}, they proposed a general algorithm to tile base multipliers previously obtained in~\cite{pascaLargeMultipliersLessDSP2009}.
However, the approach is limited to schoolbook decomposition, and is not suited to large numbers.
Authors in~\cite{kummTilingILP2017} proposed a binary ILP formulation followed by beam search heuristic tiling~\cite{kummTilingHeuristics2020} for integer multiplication.
Both run at low frequency and are not area efficient in large sizes.
Karatsuba-based tiling for DSP blocks has been explored in~\cite{kummKaratsubaRectangularMultipliers2018}, but it is not scalable for bigger operands as it does not take advantage of hierarchical decomposition.

\section{Conclusions and Future Work}
Implementing large integer multiplication in FPGAs in a way that maximizes performance while also using resources efficiently is challenging.  
In this work, we developed an approach for building efficient square base mutlipliers suited to DSP block implementation, exploiting their architectural features. 
We automate the process of generating the RTL code for tiling these bases to build large-integer multipliers in an architecture-aware manner with fast pipelined combinational logic.
The generated designs achieve high frequency, 56\% higher than previous work, while using around 17\% fewer DSP blocks.
We are releasing the tool for use by the wider research community.

In the future, we plan to leverage equality saturation to generalize this flow to arbitrary arithmetic expressions, exploiting architecture-aware rewriting in a similar manner.
Finally, for very large multipliers, we can develop a higher level pipeline structure for better scaling across SLRs.
